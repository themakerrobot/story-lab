# 그림책 공방

아이가 이야기를 짓고 그림책으로 만들어 읽어 주는 오프라인 웹앱입니다.

5~9세 아이가 이야기 카드를 골라 이야기를 만들면, 쪽마다 장면 그림이 들어간 그림책이 됩니다. 완성한 책은 읽어 주기로 듣습니다. 빌드 도구와 의존성이 없는 순수 HTML/CSS/JS이고, 정적 호스팅(GitHub Pages)만으로 동작하며, 한 번 열면 오프라인에서도 열립니다(PWA).

## 사용법

1. **✏️ 새 그림책 만들기**를 누릅니다.
2. **이야기 종류**를 고릅니다: 신나는 모험, 우주 탐험, 바닷속 여행, 생일 파티, 꼬마 탐정, 마법 학교, 공룡 시대로, 숲속 운동회, 🎲 아무거나.
3. **얼마나 큰 이야기**를 만들지 고릅니다.

   | 설계 | 인물 | 장소 | 사건 | 말썽꾼 | 고르기 | 쪽(표지·끝 포함) |
   |---|---|---|---|---|---|---|
   | 🌱 아기 작가 (5~6세) | 2 | 1 | 1 | – | 7번 | 약 10쪽 |
   | 🌿 꼬마 작가 (7세) | 3 | 2 | 2 | – | 16번 | 약 14쪽 |
   | 🌳 큰 작가 (8~9세) | 4 | 3 | 3 | 있음 | 23번 | 약 19쪽 |
   | 🎛️ 내 맘대로 | 1~4 | 1~3 | 1~3 | 켜기/끄기 | | |

4. **주인공**을 고르고 **이름**을 지어 줍니다. 이름을 지으면 그 뒤의 질문, 문장, 읽어 주기가 모두 그 이름으로 나옵니다.
5. **카드**를 고릅니다. 질문을 읽어 주고, 위쪽 점에 진행 상태와 고른 그림이 보입니다. 점의 테두리 색은 이야기의 마디를 뜻합니다(처음 초록, 사건 빨강, 해결 파랑, 끝 노랑). **🎲 골라 줘**를 누르면 대신 골라 주고, ◀로 뒤로 갈 수 있습니다.
6. **마무리**에서 책 제목(자동으로 채움)과 지은이를 쓰고 **📕 그림책 완성!**을 누르면, 책장에 저장되고 바로 읽어 줍니다.

읽기 화면에서는 다음과 같이 조작합니다.
- **🔊 읽어 주기**를 누르면 문장마다 노랗게 짚으며 읽고, 쪽을 다 읽으면 다음 쪽으로 넘어갑니다. 끝 쪽에서 멈추고, 한 번 더 누르면 멈춥니다.
- 문장을 누르면 그 문장만 읽습니다.
- 쪽은 ◀ ▶ 버튼, 키보드 ← → (Esc는 책장으로), 그림을 옆으로 밀기로 넘깁니다.
- 글에서 **이어 주는 말**(그런데, 그래서, 드디어…)은 파란 글씨, **흉내 내는 말**(바스락바스락, 쿵쿵…)은 물결 밑줄로 표시됩니다.

## 이야기가 갈라지는 방식

고정된 순서로 빈칸을 채우는 방식이 아닙니다. 카드마다 **나오는 조건**과 **바꾸는 상태**가 있어서, 앞에서 고른 것에 따라 뒤에 나오는 카드와 결말이 달라집니다.

- **장소:** 장소의 성질(바깥, 물가, 바닷속, 우주, 실내 등)에 맞는 사건만 나옵니다. 실내에서는 비가 오지 않고, 우주에서는 연료가 떨어집니다.
- **가방 속 물건:** 처음에 챙긴 물건이 나중에 해결 카드로 다시 나옵니다(손전등 → 깜깜해졌을 때). 원인과 결과를 이어 보는 장치입니다.
- **친구:** 친구마다 잘하는 것(날기, 헤엄, 힘, 빛, 요술 등)이 있어 해결 카드로 나옵니다. 한 번 나온 친구는 끝까지 함께합니다.
- **말썽꾼:** 친절하게 해결하면 친구가 되고, 그렇지 않으면 달아납니다. 결말 후보도 달라집니다.
- **기분:** 사건 뒤에 주인공의 마음 낱말(무서웠어요, 속상했어요…)을 고르면, 해결 문장이 "무서웠지만 …"처럼 이어집니다.
- **성격 × 해결 방식:** 끝에 인물이 어떻게 달라졌는지를 보여 주는 문장이 나옵니다(겁 많던 토끼가 용감해졌어요).
- **바람의 결과**(이루었어요 / 더 소중한 걸 얻었어요 / 다음에 다시 해요)와 **마지막 장면**을 아이가 고릅니다.

이야기 데이터는 `js/stories.js`에 있습니다. 주인공·해결 카드와 이야기 8종의 글감은 yjworks/kids-lab의 "이야기 만들기" 앱에서 가져와 넓혔습니다.

## 저장 위치

- 만든 책은 **이 기기의 브라우저 안**(`localStorage['storylab-v1']`)에만 저장됩니다. 서버로 보내지 않습니다.
- 브라우저 기록이나 사이트 데이터를 지우면 책도 지워집니다. 앱을 열 때 브라우저에 영구 저장을 요청합니다(`navigator.storage.persist()`).
- 저장 공간이 부족하면 알려 주고, 지금 읽는 책은 계속 볼 수 있습니다.

## 그림

- 배경은 인라인 SVG 22종입니다: 들판, 밤 마을, 숲, 바닷가, 무인도, 우주, 달, 화성, 별나라, 사탕 행성, 얼음 행성, 무지개 행성, 바닷속, 성, 방, 파티, 마법 교실, 산, 화산, 정글, 운동장, 서커스.
- 인물과 물건은 **이모지**로 그립니다. 그래서 **iPad, 안드로이드, 윈도우마다 그림이 다르게 보이고, 인쇄해도 다르게 나옵니다.**
- 그림체를 고정하려면 SVG 그림 세트로 바꿔야 합니다. 후보는 OpenMoji(CC BY-SA 4.0)와 Twemoji(CC BY 4.0)이고, 둘 다 출처 표기 의무가 있습니다. 라이선스 원문은 확인이 필요합니다.

## 목소리

설정(⚙️)에서 고릅니다. 기본값은 기기 목소리입니다.

- **📱 기기 목소리:** Web Speech API로 기기(OS)에 깔린 한국어 목소리를 씁니다. 받는 파일이 없습니다. 네트워크 목소리는 문장을 서버로 보내기 때문에, 기기 안 목소리(`localService`)를 먼저 고릅니다. 한국어 목소리가 없으면 기기 설정에서 설치하라고 안내합니다.
- **🤖 AI 목소리:** Supertonic 3(INT8)을 브라우저 안(ONNX Runtime Web, WASM)에서 돌립니다. 문장은 기기 밖으로 나가지 않습니다.
  - **모델(약 189MB)**은 Hugging Face [`leeyunjai/edge-lab`](https://huggingface.co/leeyunjai/edge-lab)의 `tts-int8/` 폴더를 커밋 `71800e5`로 고정해서 직접 받습니다. **GitHub Pages 전송량을 쓰지 않습니다.**
  - **음성 엔진**(onnxruntime-web 1.22.0, 약 22MB)은 jsDelivr에서 먼저 받고, 안 되면 같은 사이트의 `vendor/ort/` 사본을 씁니다. 두 파일은 sha256까지 같습니다.
  - 받은 파일은 Cache Storage에 보관해서, 기기마다 처음 한 번만 받고 그 뒤에는 오프라인으로 돕니다.
  - AI 목소리를 쓰는 동안 화면에 "🤖 AI 목소리"라고 표시합니다. OpenRAIL-M의 "기계가 만든 콘텐츠임을 밝힐 것" 조건 때문입니다.
  - 휴대폰이나 태블릿에서의 속도와 메모리는 실제 기기로 확인해야 합니다.

## 파일 구조

```
index.html            한 페이지 앱
css/app.css
js/core.js            조사, 글자 틀, 저장, 이모지 분리, 문장 나누기, 읽어 주기
js/stories.js         이야기 카드와 조립 엔진
js/scenes.js          자동 장면 그림(배경 SVG + 인물 배치), buildBook
js/app.js             화면 흐름
js/tts.js, tts-worker.js, tts-client.js   AI 목소리
vendor/ort/           ONNX Runtime Web 사본 (CDN이 막혔을 때)
sw.js                 오프라인 캐시
manifest.webmanifest
icons/                icon.svg, 192·512 PNG (node tests/make-icons.js로 만든다)
licenses/
tests/run.js          Playwright 테스트
```

모든 경로는 상대 경로라서 하위 경로에 배포해도 됩니다.

## 테스트

Node와 Playwright(Chromium)가 필요합니다. `python3 -m http.server`로 repo를 띄우고 확인합니다.

```bash
node tests/run.js
```

- 확인하는 항목:
  - 이야기 8종 × 설계 7가지 × 무작위로 3,360권을 만들어 깨진 값, 남은 이모지, 빈 문장, 조사(콩·토끼·달), 배경 이름, 친구가 계속 나오는지 검사
  - 화면 흐름
  - 읽어 주기: 가짜 음성 엔진 4종(정상, onend 없음, 계속 말하는 중, 완료 두 번)
  - 반응형 10가지 크기
  - XSS
  - 저장 실패
  - 오프라인
  - 콘솔 오류 0개
- 테스트 하나만 돌리기:

  ```bash
  ONLY="반응형" node tests/run.js
  ```

- AI 목소리(HF에서 모델 내려받기)까지 확인하기. 네트워크가 필요합니다.

  ```bash
  STORYLAB_MODEL=1 node tests/run.js
  ```

## 배포

`.github/workflows/pages.yml`이 `main`에 push될 때 테스트를 돌리고, 통과하면 GitHub Pages로 배포합니다. 테스트 파일과 개발 파일은 배포본에서 뺍니다. 처음 한 번은 repo 설정에서 **Settings → Pages → Source: GitHub Actions**를 골라야 합니다.
